## 2. physics.js 확장 — 완전한 쌍극자 근접장

### 2.1 공식 (Jackson 9.18, 원거리 근사 금지)

단위 x-편극 쌍극자(p̂ = x̂) 기준 커널. 항등식 `(R̂×p̂)×R̂ = p̂ − R̂(R̂·p̂)`로 전개한다:

```
E(R) = exp(ikR)/R · { k²[p̂ − R̂(R̂·p̂)] + [3R̂(R̂·p̂) − p̂]·(1/R² − ik/R) }
```

**이것을 2갈래(복사/준정전기)가 아니라 3갈래로 분리한다.** `(1/R² − ik/R)` 묶음 안에 k 의존성이 서로 다른 두 항이 섞여 있기 때문이다 — 묶음의 진폭은 `(1/R³)·√(1+(kR)²)`이고, 기준점 `r=2a`에서 `kR = 2x`이므로 x=2에서 `√17 ≈ 4.1`배가 된다. 즉 "준정전기항은 λ 무관"은 틀렸다.

| 항 | 식 (× `e^{ikR}/R`) | 거리 차수 | k 차수 | λ 의존 |
|---|---|---|---|---|
| 복사 (radiation) | `k²[p̂ − R̂(R̂·p̂)]` | `1/R` | `k²` | `λ⁻²` |
| 유도 (induction) | `[3R̂(R̂·p̂) − p̂]·(−ik/R)` | `1/R²` | `k¹` | `λ⁻¹` |
| 정전 (static) | `[3R̂(R̂·p̂) − p̂]·(1/R²)` | `1/R³` | `k⁰` | **무관** |

- `R = r_obs − r_j`, `R̂ = R/|R|`
- 거리 차수와 k 차수가 1:1로 맞물린다(`1/R³↔k⁰`, `1/R²↔k¹`, `1/R↔k²`). **k 차수는 곧 쌍극자 모멘트의 시간 미분 차수이기도 하다** — 정전항은 `p`, 유도항은 `ṗ`(전류), 복사항은 `p̈`(가속도)에 대응한다. 논문 Ⅲ.2가 인용한 Chabay & Sherwood 식 (1)은 이 중 복사항이다.
- **단, 이 3갈래 분해는 관측점 조건(`kR ≪ 1`)에 관한 것**으로, 논문 Ⅳ.1의 준정전기(파원 간 위상차 조건, `kd ≪ 1`)나 Ⅲ.2의 위상 균일성(`ka ≪ 1`, 패널 (D))과는 **적용 대상이 다르다.** 다만 셋 모두 "관련 길이 × k ≪ 1"이라는 동일한 무차원 조건이며, `λ/a`를 근사 영역의 선택자로 보는 논문의 주장을 세 번째 사례로 뒷받침한다.
- 이 3갈래 구분이 §5 (B) 항별 토글과 세 비 표시의 근거.

### 2.2 신규 함수

| 함수 | 역할 | 비고 |
|---|---|---|
| `RGD.dipoleFieldKernel(dx, dy, dz, k)` | 위 커널. §2.1의 세 항을 **분리된 필드**로 반환: `{ radiation: {ex,ey,ez}, induction: {ex,ey,ez}, static: {ex,ey,ez} }` (각 성분 `{re,im}`). 합쳐서 전체 장을 만드는 건 호출자 책임 | 순수 함수. `p̂=x̂`만 지원(이 시뮬레이션에서 유일하게 필요한 방향) |
| `RGD.scatteredFieldAt(obsPoint, grid, k, alphaTotal)` | 브루트포스 전체 합(대칭 최적화 없음). `p_j = (alphaTotal/N)·exp(ikz_j)`를 커널에 곱해 전체 grid.points에 대해 합산. 세 항을 각각 누적해 `{ radiation, induction, static }` 구조 그대로 반환(각 `{ex,ey,ez}`, 각 성분 `{re,im}`) | `verify.js` 항목 7·8·9a 전용. 임의의 3D 관측점 지원. 항목 8이 항별로 검증하므로 합치지 않고 분리 반환 |
| `RGD.scatteredFieldXZPlane(xObs, zObs, grid, k, alphaTotal, opts)` | UI 전용 최적화. **`y>0` 쌍극자만 순회**(2배 절감 — 다이폴 루프 내부). `opts.term`으로 `'full'\|'radiation'\|'induction'\|'static'` 선택. `{ex, ez}` 반환(`ey`는 관측점이 xz평면 위에 있다는 전제로 항상 0, 함수 주석에 명시) | y 대칭만 쓴다. **x 대칭은 이 함수 안에 넣지 않는다** — 단일 관측점을 받는 함수라 관측점 쌍을 만들 수 없다. x 대칭은 호출자(렌더 루프, script.js)의 몫 — §4 참고. `scatteredFieldAt`은 검증용이므로 대칭 최적화 없이 그대로 둔다 |

`alpha` = `alphaTotal/N` (개별 분극률) — **`alphaTotal`을 그대로 커널에 곱하면 안 된다.** 세 함수 모두 주석에 이 구분을 명시한다(1단계의 "편광 인자 이중 계산 금지" 주석과 같은 성격의 방어적 주석).

### 2.3 y 대칭과 x 대칭은 적용 대상이 다르다 (코드 주석에 그대로 인용)

두 대칭을 같은 자리(다이폴 루프)에 넣으면 안 된다 — 적용되는 곳이 다르다:

- **[y 대칭] → 다이폴 루프에 적용** (`scatteredFieldXZPlane` 내부). 커널이 `dy`에 대해 `E_x`, `E_z`는 짝함수이고, 다이폴 위치가 `y_j`↔`−y_j`로 짝지어져 있고 위상이 `z_j`에만 의존하므로(짝의 진폭이 같음), `y_j>0`인 다이폴만 순회하고 2배 하면 된다. `E_y`는 홀함수라 상쇄되어 0.
- **[x 대칭] → 관측점에 적용** (렌더 루프, `script.js`). 다이폴별로 `x_j`와 `−x_j`를 짝지어 절감하려는 시도는 **틀렸다** — 관측점 `x_o`가 고정된 상태에서 `dx = x_o − x_j`와 `x_o − (−x_j) = x_o + x_j`는 부호만 다른 관계가 아니다(`x_o = 0`일 때만 성립). 실제로 성립하는 것은 **전체 합**에 대한 관계다:

  ```
  E_x(−x_o, z_o) = +E_x(x_o, z_o)
  E_z(−x_o, z_o) = −E_z(x_o, z_o)
  ```

  이 관계는 두 조건이 함께 있어야 성립한다 — 커널이 `dx`에 대해 `E_x`는 짝함수·`E_z`는 홀함수라는 성질과, 격자가 `x→−x` 대칭이라는 조건. 전체 다이폴 합에 대해서만 성립하므로(개별 다이폴 쌍이 아니라), **관측 격자에서 `x_o≥0` 열만 계산하고 좌우로 부호 반전해 복사**하는 형태로만 쓸 수 있다. (비구형 산란체로 확장하면 격자의 x대칭이 깨지므로 이 최적화는 무효가 된다 — 확장 시 주의.)

y 대칭(2배, 다이폴 루프)과 x 대칭(2배, 관측 루프)을 곱하면 4배 절감 — 단, 서로 다른 두 루프에서 각각 나온다.

## 3. verify.js 항목 7·8·9

### 항목 7 — 원거리 한계 (복사항 검증)

- 관측 거리: `r = max(30a, 100/k)` — **`r = 30a`만으로는 부족**(원거리 조건은 `r≫a`뿐 아니라 `kr≫1`도 필요). `λ/a=1000`이면 `k = 2π/1000 = 0.00628`, `r=30a`에서 `kr = 0.19`로 오히려 준정전기 영역이 되어버리므로 `k·r` 하한을 둔다. 하한을 `kr≥50`이 아니라 **`kr≥100`**으로 잡는 근거는 아래 오차식.
- 비교식: `|E_sca|² 목표값 = (k²·(alphaTotal/N)/r)² · dSigmaDOmega(points, k, θ, φ)` — 개별 분극률(`alphaTotal/N`)을 써야 함(`alphaTotal` 그대로 쓰면 `N²`배, 약 1.8e7배 어긋남).
- 평가 지점: **x=2.0**과 **x=0.0063**(sweep 양 끝) 두 지점.
- 임계값: 1%.
- 사용 함수: `RGD.scatteredFieldAt` (브루트포스, 대칭 최적화 없는 경로 — 검증 대상 커널과 UI 최적화 경로가 분리되어 있어야 이 검증이 커널 자체를 검증하는 의미가 있음).

#### 평가 각도 제한과 그 근거 (제한하지 않으면 반드시 FAIL)

`kr=100`에서도 근접장 성분이 남아 있다. 단일 쌍극자 장을 `R̂`/`t̂` 정규직교 기저로 분해하면(`u = kR`, `c = cosΘ`, `s = sinΘ`) 횡성분 `k²s[1 − 1/u² + i/u]`, 종성분 `k²c[2/u² − 2i/u]`이므로:

```
|E|² = k⁴[ sin²Θ·(1 − 1/(kR)²) + 4cos²Θ/(kR)² ] + O(1/(kR)⁴)
상대 오차 = (4cos²Θ/sin²Θ − 1) / (kR)²
```

**`φ=0` 평면의 `θ=90°`는 `n̂ = x̂` = 편광축이라 `sin²Θ = 0`(쌍극자 널)이다.** 목표값이 0인데 계산값은 0이 아니므로 상대 오차가 발산해 반드시 FAIL한다. 따라서 **`sin²Θ ≥ 0.25`인 각도만 평가**한다:

- `φ=90°` 평면: `sin²Θ = 1 − (n̂·x̂)² = 1` — 전 각도 안전
- `φ=0` 평면: `sin²Θ = cos²θ` — `θ ≤ 60°` 또는 `θ ≥ 120°`만 사용

이 조건에서 `4cos²Θ/sin²Θ ≤ 12`이므로 최대 오차는 `11/(kR)² = 0.11%`, 임계값 1% 대비 9배 여유다.

### 항목 8 — 정전기 극한 (정전항·유도항 검증, 신규)

- 항목 7은 복사항(`k²/R`)만 검증한다. `1/R²`(유도), `1/R³`(정전) 항은 전혀 검증되지 않는데 (A)(B)(C) 패널의 존재 이유가 바로 이 두 항이므로 별도 검증이 필요하다.
- `kR = 1e-4`에서 두 가지를 확인한다. **두 항목 모두 근사가 아니라 정확한 항등식이므로 임계값은 기계 정밀도(1e-12)로 잡는다:**

  - **(8a) 정전항의 각도 구조와 `1/R³` 스케일링**

    ```
    |static − [3R̂(R̂·p̂) − p̂]·e^{ikR}/R³| / |[3R̂(R̂·p̂) − p̂]/R³| < 1e-12
    ```

    **기준식에 `e^{ikR}`를 반드시 포함한다.** `static` 항은 `[3R̂(R̂·p̂) − p̂]·(1/R²)·e^{ikR}/R`이라 `e^{ikR}`를 이미 갖고 있는데, 기준식에서 빼면 `|e^{ikR} − 1| ≈ kR = 1e-4`가 그대로 상대 오차로 남아 1e-6 임계값을 100배 초과한다(달성 불가능한 검증이 됨). `e^{ikR}`를 포함하면 정확한 항등식이 되어 각도 구조와 `1/R³` 스케일링을 기계 정밀도로 검증할 수 있다.
    여러 방향(`R̂·p̂ = 0, 0.5, 1`)과 여러 `R`에서 확인한다.

  - **(8b) 유도항의 `k` 스케일링**: `|induction|/|static| = kR`. 두 항이 같은 벡터 인자 `[3R̂(R̂·p̂) − p̂]`와 같은 `e^{ikR}`를 공유하므로 이 비 역시 **정확한 항등식**이다(계수만 `(−ik/R)` 대 `(1/R²)`). `kR=1e-4`에서 이 비가 `1e-4`인지 상대 오차 < 1e-12로 확인.

- 항목 7(`kR≫1`)과 항목 8(`kR≪1`)이 양쪽 극한을 조이고, (8b)가 중간 차수인 유도항의 k 스케일링을 직접 고정한다.

### 항목 9 — UI 최적화 경로(대칭) 검증

항목 7·8은 `scatteredFieldAt`(브루트포스)만 검증한다. 정작 화면을 그리는 `scatteredFieldXZPlane`(y 대칭)과 렌더 루프의 x 거울 관계는 아무것도 검증하지 않아, 나중에 성능 최적화를 건드릴 때 조용히 깨질 수 있다.

- **(9a) y 대칭 최적화**: `scatteredFieldXZPlane(x, z, …)`와 `scatteredFieldAt({x, 0, z}, …)`의 `(ex, ez)` 비교. 여러 `(x, z)`와 `x = 2.0`·`0.0063` 양쪽에서.
- **(9b) x 거울 관계**: `scatteredFieldXZPlane(+x, z)`와 `(−x, z)`를 비교해 `E_x(−x) = +E_x(x)`, `E_z(−x) = −E_z(x)`가 성립하는지.
- **임계값은 1e-12가 아니라 `1e-10`.** 두 경로는 덧셈 순서가 달라 약 1400항 합산에서 반올림 잡음이 `2e-13`까지 올라간다 — 1e-12는 여유가 5배뿐이라 오검출 위험이 있다. 느슨하게 잡아도 잃는 것이 없다: 대칭 버그는 미묘하지 않아서 `×2` 누락은 정확히 2배, 부호 오류는 200% 어긋난다. **`1e-13`(반올림 잡음)과 실제 버그(`O(1)`) 사이가 텅 비어 있다.**
- 규격화 주의: 성분 하나가 대칭 때문에 정확히 0이 되는 지점이 있으므로(예: `x=0`에서 `E_z=0`) 성분별 상대 오차는 정의되지 않는다. **항별 최대 크기로 규격화**한다.

> **(9b)의 한계 — 반드시 인지할 것**: x 대칭은 `script.js` 렌더 루프에 있으므로 Node인 `verify.js`가 직접 검증할 수 없다. **(9b)가 검증하는 것은 관계식 자체이지, 렌더 루프가 그것을 올바로 적용했는지가 아니다.** 렌더 루프의 부호 실수는 아래 런타임 어서션으로 잡는다.
>
> **런타임 어서션**: `script.js`에 개발용 플래그 `DEBUG_SYMMETRY`(기본값 `false`)를 둔다. `true`일 때, 미러링으로 채운 열 중 하나를 `scatteredFieldXZPlane`으로 직접 계산해 비교하고 상대 편차가 `1e-10`을 넘으면 `console.warn`. 기본값이 `false`이므로 성능에 영향이 없다.

**항목 7·8·9를 모두 통과해야 1행 UI 구현으로 넘어가고, 1행 UI가 끝나야 2행 재배치로 넘어간다** (사용자 지시 그대로).

## 4. 표시 격자·마스킹·성능

- `nd_display = 14` (`RGD.buildDipoleGrid(1, 14)` 재사용, N≈1400). `k·h = 0.286`으로 x=2에서도 `k·h≤0.3` 제약 만족
- **`nd_display`는 1행(A)(B)(C) 근접장 렌더링 전용이다.** 2행의 (D) 내부 위상 지도와 (E) 위상자 합은 **물리 격자 `nd = 20`**을 쓴다 — (E)가 `nd=14`를 쓰면 (F) 산란 패턴과 다른 격자의 결과를 나란히 놓게 되고, (D)는 `nd=20`의 `columns`가 약 314개라 렌더링이 이미 가볍다
- 표시 영역: z ±5a, x ±3a
- 화면 격자: **120(z)×72(x)** — 표시 영역이 `10a×6a`(비 1.667)인데 처음 안이던 `120×80`(비 1.5)은 픽셀이 정사각형이 아니어서 `120×72`(비 1.667)로 수정
- **화면 x 표본은 셀 중심 배치**(1단계 물리 격자와 같은 방식) — §2.3의 좌우 반전이 정확하려면 x 표본점이 `x=0`에 대해 대칭이어야 한다:

  ```
  h_screen = 6a/72,   x_i = −3a + (i + 0.5)·h_screen,   i = 0 … 71
  ```

  이러면 `x=0` 표본이 존재하지 않고 36쌍이 정확히 대칭이 된다(1단계 셀 중심 배치가 `Im(F)/N=0`을 보장했던 것과 같은 논리)
- y 대칭(다이폴 루프, 2배)과 x 대칭(관측 루프, 2배)을 함께 적용해 4배 절감: 다이폴은 `y_j>0`만(약 700개), 관측점은 `x_o≥0`인 36열×120행=4320점만 계산하고 나머지는 §2.3 부호 규칙으로 복사. 총 계산량 `약 700 × 4320 ≈ 302만 쌍`으로 체감 지연 최소화
- **세 항을 화면 점마다 캐싱한다.** 커널이 세 항을 함께 반환하므로 한 번 계산할 때 `radiation`/`induction`/`static`을 모두 저장해 두면, (B)의 [전체]/[복사]/[유도]/[정전] 전환이 **재계산 없이 표시만 바꾸는 일**이 된다. 저장량은 `4320점 × 3항 × 2성분(ex,ez) × 2(복소) ≈ 5만 float`로 부담이 없다(좌우 반전까지 펼쳐도 10만). 명시하지 않으면 토글마다 302만 쌍을 다시 도는 구현이 나온다. 재계산은 λ가 바뀔 때만 한다
- `|r| < 1.5a` 내부는 회색 마스킹 + "모형 적용 범위 밖" 표기, 마스크 안쪽 점은 근접장 계산 자체를 생략(성능 + 어차피 안 보임)
- **마스크 반경은 1.5a로 고정한다 — 축소하지 않는다.** `nd_display=14`, 셀 중심 배치이므로 최외곽 쌍극자는 `r ≈ 0.93a`(최대 좌표 `−1+13.5·h = 0.9286a`, 모서리 조합까지 포함하면 `r ≈ 0.998a`)에 있다. 마스크를 `1.2a`로 줄이면 최근접 쌍극자까지 거리가 `0.21a`에 불과해 `1/R³` 발산 때문에 **단일 쌍극자 하나가 전체 장의 최대 13%**를 차지한다 → 격자점 위치가 알갱이 무늬로 드러나 논문 그림으로 쓸 수 없다. `1.5a`에서는 이 비율이 1~3%로 문제없다.
- 마스크 반경 확정 절차: 1.5a로 1차 렌더링 → 회색 원이 화면을 지배하면 **대안은 표시 영역 확장 하나뿐**이다(`z ±6a`, `x ±4a` = `12a×8a`, 비 1.5). 이 경우 화면 격자도 **`120(z)×80(x)`**으로 함께 바꿔야 픽셀이 정사각형으로 유지된다 — **`x`만 ±4a로 넓히고 `z`를 ±5a로 두면 `10a:8a = 1.25`가 되어 120×80(=1.5)과 어긋나고 마스크가 타원으로 렌더링된다.**
  - (`1.2a`가 꼭 필요해지면 `nd_display`를 20 이상으로 올려야 한다. `k·h`는 더 작아지므로 제약상 안전하고 계산량만 약 2배 — 이번 범위에서는 선택하지 않는다.)

**확정: 표시 영역은 `10a×6a`(`z ±5a`, `x ±3a`), 화면 격자 `120×72`를 유지한다.** 두 안을 미리보기 PNG로 렌더링해 비교한 뒤 내린 결정이며, 근거는 마스크 면적 비율(11.8% — 판단 기준이 아님)이 아니라 다음 넷이다:

- **확장 영역이 거의 비어 있다.** 근접장이 `1/R³`이므로 `r=3a`에서 `|E_sca|/|E_inc| ≈ 3.7%`, `r=4a`에서 `1.6%`다. (A)(B)(C)가 색 스케일을 공유하므로 넓힌 영역은 사실상 백지로 렌더링된다
- **해상도**: 픽셀이 `0.0833a`(확장안은 `0.1a`). 근접장 구조가 입자 근처에 몰려 있으므로 이쪽이 유리하다
- **종횡비**: 1행 패널이 약 1.72이므로 `1.667`이 `1.5`보다 잘 맞는다
- **논문 출력 모드에서 패널이 더 작아지므로**, 화면을 물리로 채우는 쪽이 유리하다

### 근접장 코드의 독립적 방증 (실측으로 확인됨)

화면 가장자리 `z=5a`에서 `kr=1`이 되는 지점은 `k = 1/5a` → **`λ/a = 2π·5 ≈ 31.4`**다. 따라서 `λ/a ≳ 31`에서는 화면 전체가 근접 영역이어야 하고, `λ/a=π`에서는 가장자리가 `kr=10`이라 복사 로브가 보여야 한다. 미리보기 렌더링이 정확히 그렇게 나왔다(`λ/a=40`에서 입자에 붙은 정전기 쌍극자 모양만 남고 바깥으로 뻗는 로브가 전혀 없음, `λ/a=π`에서는 복사 로브 + 전방 산란 비대칭). 검증 7·8·9와 독립적인 방증이다.
- 슬라이더는 `input`이 아니라 `change` 이벤트에서 재계산 (기존 시뮬레이션과 동일한 관례)

## 5. 패널별 상세

### (A) 입사파

- 표시량: `Re(E_x)` 순간 스냅샷(t=0), diverging 컬러맵(빨강-파랑)
- **파장 눈금 막대(필수)**: "λ = _a" 양방향 화살표. 창(10a)보다 길면 화살표가 패널 밖으로 잘려나가게 그대로 둔다 — 그 잘림 자체가 "파장이 표시 범위보다 크다"는 메시지
- 자동 캡션(`λ/a ≳ 20`일 때만 표시): "파장이 표시 범위보다 커서 입사파가 균일하게 보입니다"

### 1행 공통 — 세 패널의 이미지 영역은 픽셀 단위로 동일해야 한다

1행의 존재 이유가 "입사파 / 산란파 / 중첩을 **같은 스케일로 나란히 비교**"이므로, 크기가 다르면 비교 자체가 성립하지 않는다(논문 표 3도 세 칸이 같다). 따라서:

- 세 패널의 세로 구조를 동일하게 맞춘다: `제목 + 이미지 영역(flex:1) + 캡션(고정 높이)`
- (B)의 지표 줄·배율 배지·경계원 라벨, ⓘ 설명은 모두 **이미지 영역 안의 오버레이**로 띄운다. 문서 흐름에 넣으면 그 패널의 이미지만 작아진다
- **상시 노출 캡션은 패널당 한 덩어리로 제한**한다. 긴 설명은 ⓘ 토글 안으로 — 설계상 "캡션 필수"는 단서가 **존재해야** 한다는 뜻이지 항상 펼쳐져 있어야 한다는 뜻이 아니다. 논문 출력 시에는 그림 캡션 텍스트로 들어가지 그림 안에 넣지 않는다

### (B) 산란파

- 표시량 토글: **[전체] / [복사] / [유도] / [정전]** 4개 — `scatteredFieldXZPlane`의 `opts.term`(`'full'|'radiation'|'induction'|'static'`)을 그대로 노출
- 색스케일은 (A)(C)와 공유(입사파 진폭=1 기준 고정)
- 산란파가 약해 안 보일 경우를 대비한 별도 "표시 배율" 토글, 배율값을 패널에 크게 표기. **이 배율은 (B) 패널의 렌더링에만 적용된다** — (C)에는 적용하지 않는다
- **`kR = 1` 경계원**: 반지름 `R = 1/k = λ/2π`인 점선 원 + "kR = 1" 라벨. 원이 화면 밖이면(`R >` 화면 모서리 거리 `√(5²+3²) = 5.83a`, 즉 `λ/a > 36.6`) "이 화면 전체가 반응성 근접 영역" 배지, 마스크(1.5a) 안이면(`λ/a < 9.42`) "이 화면 전체가 복사 영역" 배지
- **고정 기준점 지표 — (C)가 아니라 (B)에 둔다.** 세 비는 전부 "산란장의 구성"에 관한 값이므로 (B)에 속한다. (B)에는 이미 항별 토글이 있으므로 같은 세 항의 숫자를 옆에 두면 **토글이 스스로를 설명하게 된다.** 기준점 마커(`기준 r=2a`)도 (B) 이미지에 표시한다
  - 기본은 **숨김**. 제목 옆 "수치" 버튼으로 켜고, 토글 상태는 세션 동안 유지(λ를 바꿔도 꺼지지 않는다)
  - 켰을 때 이미지 아래 오버레이로 한 줄:
    `기준 r=2a │ 머무는 장: 정전 1.26e-1 · 유도 3.51e-2 │ 나가는 장: 복사 1.17e-2`
  - 최댓값이 아니라 고정 기준점을 쓰는 이유: 최댓값은 마스크 경계에서 나와 마스크 반경에 종속되므로 논문에 실을 수 없다
  - **반드시 전체 다이폴 합으로 계산한다** — `dipoleFieldKernel`은 쌍극자 **하나**의 커널이므로 이걸 한 번 호출해 지표를 만들면 화면에 그리는 전체 합과 어긋난다(`x≪1`에서는 우연히 비슷하지만 `x=2`에서는 `exp(ikz_j)` 위상 변화 때문에 명확히 달라진다). 단일 점 3회 호출이므로 비용은 무시할 수준:

    ```javascript
    RGD.scatteredFieldXZPlane(0, 2*a, grid, k, alphaTotal, {term: 'static'})
    RGD.scatteredFieldXZPlane(0, 2*a, grid, k, alphaTotal, {term: 'induction'})
    RGD.scatteredFieldXZPlane(0, 2*a, grid, k, alphaTotal, {term: 'radiation'})
    ```

  - 정전 비 `|E_static(r=2a)|/|E_inc|` — **λ 무관**(엄밀히 `k⁰`) · 유도 비 `λ⁻¹` · 복사 비 `λ⁻²`
- 상시 캡션: **"멀리까지 나가는 것은 복사장뿐이다. 정전장과 유도장은 한 주기 안에 나갔다 되돌아오는 저장 에너지여서 알짜 전력을 실어 나르지 않는다."**

#### 교차점 (실측으로 확정된 값)

점쌍극자라면 `+z축`에서 `R̂ = ẑ ⊥ p̂ = x̂`, 즉 `R̂·p̂ = 0`이므로 세 항의 크기가 `k²/R`, `k/R²`, `1/R³`이 되어 인접한 두 비가 둘 다 정확히 `kR`이고, `kR = 1`(`r=2a`, `a=1`이므로 `λ/a = 4π ≈ 12.566`)에서 세 값이 한 점에서 동시에 만나야 한다.

**실제 격자 합에서는 두 번으로 갈라진다** (`λ/a` 11→13 훑기로 확인):

| 교차 | λ/a | kR (= 2k) |
|---|---|---|
| 정전 = 유도 | **11.182** | 1.1238 |
| (점쌍극자 예측 — 셋 동시) | 12.566 | 1.0000 |
| 유도 = 복사 | **13.345** | 0.9417 |

두 교차가 점쌍극자 값을 양쪽에서 감싼다. 정전 비는 훑기 전 구간에서 `1.2555e-1`로 고정되어(점쌍극자 `1/8 = 0.125` 대비 `+0.4%`) λ 무관성과 규격화가 함께 확인된다.

> **"실효 거리"로 인과를 설명하지 말 것.** `R_eff = 1/k`는 결과를 기록하는 편의적 표기이지 기제가 아니다. `λ/a=12.5`에서 점쌍극자 대비 편차는 정전 `+0.5%`, 유도 `−10.6%`, 복사 `−5.1%`로 **거리 차수 순서를 따르지 않는다**(유도가 가장 억제됨). 관측점 `(0,0,2a)`에서 축 위 쌍극자는 위상 `k(z_j + R_j) = 2ka`로 모두 동일하고 위상 흩어짐은 축 바깥 쌍극자에서만 오는데, 정전·유도의 각도 인자 `[3R̂(R̂·p̂) − p̂]`와 복사의 `[p̂ − R̂(R̂·p̂)]`가 서로 달라 축 바깥 기여의 상쇄 정도가 거리 차수만으로 정해지지 않기 때문이다. 문서·캡션에는 **관측된 사실만** 적고, 이 각도 인자 차이는 각주 수준으로만 언급한다.

### (C) 중첩 결과 (입사파 + 산란파)

- 표시량: (A)+(B)의 전체 장 합. **항별 토글도, 표시 배율도 (C)에는 적용하지 않는다** — (C)는 항상 세 항을 모두 합친 원본값(배율 1)으로 `E_inc + E_sca`를 계산한다. 배율이 걸린 산란파를 더하면 (C)가 물리적으로 무의미해진다
- **(C)에는 이미지 + 캡션 한 줄만 남긴다.** 수치와 기준점 마커는 (B)로 옮겼다 — (C)의 본업은 "중첩 결과가 입사파와 거의 같아 보인다"는 시각적 메시지이고, 수치가 붙을 자리가 아니다
- 상시 캡션: **"파장이 길어지면 물체는 여전히 반응하지만, 그 반응이 밖으로 전파되지 않아 전체 장이 입사파와 거의 같아진다."**
- ⓘ 오버레이에 들어갈 부가 설명:
  - "비의 절댓값은 규격화에 의존한다(`α_total=1`은 `a³`과 같으며 완전도체 구의 최대 분극률에 해당). 의미 있는 것은 값 자체가 아니라 정전 비가 λ에 무관하다는 사실이다"
  - 위 교차점 표(11.182 / 13.345)와 "이 위치는 기준점(`r=2a`) 선택에 좌우되므로 물리적 경계가 아니다"

### (D) 내부 위상 지도

- `columns[{x,z,m}]` 산점도. 색 = `cos(k·z)`, 크기 = `m`. 기존 API 그대로 재사용, 신규 계산 없음. 물리 격자 `nd=20` 사용(§4, `columns` 약 314개)

### (E) 위상자 합

- `exp(i q·r_j)`를 이어 붙인 누적합 경로(phasor walk). 전용 θ 슬라이더(전역 λ 슬라이더와 별개). 물리 격자 `nd=20` 사용(§4)
- **`φ = 0`으로 고정한다.** `|F|`는 φ에 무관하지만 개별 위상 `q·r_j`는 q 방향에 의존하므로(walk 경로 모양이 φ마다 달라짐), 재현성을 위해 φ를 고정해 둔다
- **그리는 순서**: `q̂·r_j` 오름차순 정렬 후 연결(위상 단조 증가 → 나선 모양). `θ→0`에서는 `q=0`이라 방향 미정의이므로 이때는 `z_j` 순서로 대체
- **정규화**: 각 위상자의 길이를 `1/N`로 두어 walk 전체 경로 길이가 1이 되게 한다. `θ=0`에서는 모든 위상자가 정렬되어 길이 1의 직선이 되며, 이것이 기준선이다

### (F) 산란 패턴

- 극좌표 `dσ/dΩ`, 편광면(`φ=0`)·수직면(`φ=90°`) 두 곡선. `+z`(전방)가 오른쪽, `θ=0` 값으로 규격화(두 곡선 모두 `θ=0`에서 정확히 1)
- **`|F(θ)|²`를 한 번만 계산하고 편광 인자만 다르게 곱한다** — `|F|`는 θ에만 의존하고 φ에는 무관하므로(`|q| = 2k·sin(θ/2)`):

  | 면 | `sin²Θ` | `dσ/dΩ` |
  |---|---|---|
  | 수직면 `φ=90°` | `1` | `|F(θ)|²` |
  | 편광면 `φ=0` | `cos²θ` | `|F(θ)|²·cos²θ` |

  `φ=0` 슬라이스이므로 `formFactorPhi0Columns`(316항, 4224항 대신)를 그대로 쓸 수 있다 — 근사가 아니라 정확한 항등식이다. 이렇게 하면 (E)의 위상자 합과 **같은 수를 공유**하게 되어 두 패널의 대응이 코드 수준에서 보장된다(실측 정합 `3.6e-14`).
- (E)의 θ 슬라이더와 연동: θ 마커를 **수직면(`φ=90°`) 곡선 위**에 표시 — 그 곡선이 `|F(θ)|²` 그 자체(편광 인자=1)이므로 위상자 크기의 제곱과 직접 대응
- 캡션: "두 곡선의 차이는 쌍극자 복사의 편광 인자이며, 공통된 모양은 모두 위상자 합에서 온다"

### 2행 렌더링 방식

세 패널 모두 **canvas**로 그리고, `blitSquare`가 셀 안에서 `min(폭, 높이)` 변을 잡아 중앙 정렬한다(셀보다 작아도 무방). 1행과 렌더링 경로를 하나로 유지하기 위한 선택이며, 논문 출력 모드에서 벡터 출력이 필요하면 같은 데이터로 SVG를 따로 그리면 된다(출력 모드는 이번 범위 밖).

렌더링 검증(실측): (E) walk 끝점 `|F|/N`과 (F) 곡선 `√(fCurve)`가 `3.6e-14`까지 일치하고, `fCurve[0] = 1.000000000000000`이다. `λ/a=1000`에서 수직면이 모든 θ에서 정확히 `1.0`(완전한 원), 편광면이 `1.0/0.5/0.0/0.5/1.0`(정확한 `cos²θ`)로 교과서적 레일리 쌍극자 패턴이 나온다.
